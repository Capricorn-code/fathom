# ADR-002: 機能A→機能Bの直列開発

## 状況

機能A(無料・集客)と機能B(有料・収益)をどの順序で開発するか。並行開発すれば早く両方揃うようにも見えるが、開発リソースは個人の限られた時間である。

## 決定

**直列で開発する。** まず機能Aを完成させて公開し(M2)、その後に機能Bと課金に着手する(M3)。並行しない。

## 却下した代替案

- **機能A/Bの並行開発:** リソースが分散して両方が中途半端になり、どちらもリリースに到達しないリスクが高い。機能Bの価値検証は機能Aで集客できてからでよく、先に作っても検証相手がいない。クリティカルCUJが機能A側に1本だけ定義されていることとも整合しない。
