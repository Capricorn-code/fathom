# ADR-005: マスキングは3段階で行う

## 状況

[ADR-003](./003-local-analysis-first.md) でLLM送信をSessionDigestに限定したが、Digest内の項目にも機微度の差がある。一律の扱いでは「安全すぎて役に立たない」か「便利だが漏れる」のどちらかに倒れる。

## 決定

機微度に応じた**3段階のマスキング**を行う:

1. **構造的に送らない:** tool_result生データ / コード本体 / diff / attachment(型に含めない)
2. **変換して送る:** ファイルパスの一般化 / エラーメッセージのテンプレート化
3. **プレビュー後に送る:** typedプロンプト / プロジェクト名(ユーザーが送信前に確認・編集)

実装はM2。M1では `packages/masking` の骨組みのみ。プレビューと実送信で同一の純関数を共有するため、maskingはcoreに依存しない独立パッケージとする。

## 却下した代替案

- **単一の正規表現マスキング:** パスやプロンプトの機微は文脈依存で、パターンマッチだけでは漏れる。段階を分け「そもそも型に含めない」層を作る方が確実。
