# 機能A: セッションサマリ(機能設計書)

AIとの開発履歴から「何をやったか」を言語化する機能。無料で提供する集客装置([product.md](../product.md))。

機能B(検証)の設計書は M3 着手前に `feature-b.md` として作成する。

## M1スコープ

**ゴール:** JSONL 1ファイル → セッションサマリMD出力。

### CLI

```
fathom summary <jsonlパス>
```

- [ADR-006](../adr/006-optin-allowlist.md) 準拠: 許可リスト(`~/.config/fathom/config.json`)にないプロジェクトのログは拒否する
- **初回対話セットアップ:** 設定なしで実行された場合、`~/.claude/projects/` の一覧を表示し「解析対象を選択(業務プロジェクトは選ばないでください)」と促して許可リストを生成する

### 処理内容

1. ストリーム読込([input-format.md](./input-format.md))
2. 抽出・集計:
   - typedプロンプト(人の発話)
   - tool_useのツール名・ファイルパス
   - tool_resultのis_error(エラー数と解決数)
   - usage(トークン量)

### MD出力

含める項目: 期間 / 指示一覧 / 触ったファイルと回数 / エラー数と解決数 / トークン量。

**文言は帰属を断定しない**([product.md](../product.md) の設計思想)。例: 「あなたはXを実装した」ではなく「Xの実装が行われた。あなたの指示n回」。

### M1でやらない(広げるな)

- 会話木の厳密復元(線形読みで妥協)
- sidechain除外の厳密化
- マスキング実装([ADR-005](../adr/005-masking-three-stages.md) はM2で実装)
- LLM連携
- 複数ファイル・週次集計

## 完了条件

開発者がこのfathomリポジトリ自身の開発ログを食わせ、読めるMDが出ること(ドッグフーディング)。
