## こんな不安、ありませんか

Claude Codeを使い始めてから、開発速度は明らかに上がりました。でもある日、ふと気づいたんです。

**「今日一日、自分は何をやったんだっけ?」**

ログを見返そうにも、ターミナルの履歴は流れ、会話は膨大。振り返る手段がない。そして、もっと嫌な不安が続きます。

**「この実装、人に説明できるか…?」**

AIに書かせたコードが動いている。レビューも通った。でも「なぜこの設計なのか」を聞かれたら、自分の言葉で答えられる自信がない — この感覚、心当たりのある人は多いと思います。

この不安を解消するために、**fathom**(ファゾム: 「水深を測る」+「深く理解する」の両義)というCLIを作りました。

## fathomは何をするか

Claude Codeは、すべてのセッションを `~/.claude/projects/` にログ(JSONL)として自動保存しています。fathomはこのログを読んで、**「あなたの指示」と「AIの応答」を対にした、5分で読めるサマリ**を生成します。

```sh
npm install -g @haruto-y/fathom   # Node.js 22+

fathom summary <ログのJSONLパス>         # Markdownで出力
fathom summary <ログのJSONLパス> --html  # ブラウザで読めるHTMLを生成
```

<!-- ここにスクリーンショット①: --htmlのサマリ画面 -->

サマリの主役は「会話の流れ」です。

```markdown
### 12. テストが落ちてる、直して
原因はモックの初期化順でした。beforeEachで…
▶ 応答の全文(38行)

### 13. なるほど、ついでにCIも設定して
GitHub Actionsのワークフローを追加します。…
```

時系列に自分の指示とAIの応答が並ぶと、面白いことが分かります。**自分が「設計を指示した」場面と、「丸投げした」場面が、はっきり区別できる**んです。末尾には触れられたファイル・エラー数・トークン量(延べ)などの統計も付きます。

## こだわり: 「あなたはXを実装した」とは絶対に書かない

fathomのサマリは、冒頭にこう宣言します。

> このサマリはセッションログの機械的な集計です。記録された操作の主体(あなた/AI)を断定しません。

「編集が行われました。あなたの指示: n回」— この回りくどい文体は意図的です。

AIとの開発履歴を「自分の実績」に変換するツールは、簡単に**盛る道具**になります。fathomはその逆を向いていて、「AIを使えばスキルが身についている」とは前提しません。ログが語るのは「何が行われ、あなたが何回・どんな指示をしたか」までで、**それを説明できるかどうかは、読んだあなた自身が判定する** — 発見ではなく、区別と確信のためのツールです。

## プライバシー設計の話

セッションログを読むツールなので、ここは真面目に設計しました。

1. **完全ローカル。** 解析もサマリ生成もすべて手元で完結します。LLM APIも呼びません。そもそも外部通信するコードが存在しません
2. **デフォルト全拒否のopt-in。** 初回実行時にプロジェクト一覧から「解析を許可するもの」を選ぶ対話セットアップが起動し、**選んだプロジェクト以外のログはパーサーが読みません**

<!-- ここにスクリーンショット②: 初回セットアップの対話 -->

3. **業務コードは対象外。** セットアップ画面でも「業務プロジェクトは選ばないでください」と明示しています。個人リポジトリ・OSSでの利用を前提にした設計です

## 開発の裏話: 自分で使って「何も得れない」と言った

このツール、開発の全工程をClaude Codeでやり、**自分の開発ログを自分に食わせる**ドッグフーディングをしました。初回の結果は散々でした。

最初のバージョンは「指示43回、76ファイル編集、エラー6件」のような機械集計の羅列で、自分で見て**「正直、何も得れない」**という感想しか出なかったんです。原因を考えると2つありました。

1. **自分の指示しか表示されず、AIの応答がなかった** — 対話の片側だけ見ても何も思い出せない
2. **ターミナルのMarkdownは読む気にならない** — 画面が必要だった

そこで「指示→応答の対」表示とHTML出力を実装し、3回目のドッグフーディングでようやく「5分で振り返れる」と自分で納得できるものになりました。**数字の羅列は意味を語らない**という当たり前の学びに、作ってみて初めてたどり着いた形です。

## 今後

- **画面の強化:** 現在のHTML出力は暫定で、ゆくゆくはWebサービスとして見やすくしたい
- **複数セッションの横断集計:** 「この1ヶ月でスキルがどう動いたか」の言語化
